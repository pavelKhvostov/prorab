# CLAUDE.md — prorab-landing

> Главный конфиг проекта для Claude Code. Читается автоматически на старте сессии.
> Держим ≤120 строк (методичка: длиннее — context rot).

## Проект
Одностраничный лендинг прораба (ремонты). Без БД в v1. Цель страницы — заявка на замер.

## Источник истины
- `PROJECT_IDEA.md` — Layer 1 (зачем и для кого)
- `SPECIFICATION.md` — Layer 2 (технический чертёж: секции, типы полей, контракт `submitLead`, раскадровка анимаций, edge cases)

**Правило:** перед любой генерацией кода — прочитать `SPECIFICATION.md`. Несоответствие спеке = ошибка, а не «улучшение». Если спека противоречива — остановиться, спросить, не «домысливать».

## Стек
- Next.js 14+ (App Router), TypeScript strict
- Tailwind CSS
- Framer Motion + GSAP/ScrollTrigger + Lenis (анимации)
- Деплой: Vercel
- БД нет (в v1)

## Правила проекта (жёсткие)
1. **Spec-First.** Никакого кода без записи в спеке.
2. **No TODO.** Заглушки только там, где явно отмечено в спеке (v1 `submitLead` → лог).
3. **Один источник стиля.** Только Tailwind + токены из `tailwind.config.ts`. Без CSS-in-JS, без хардкода цветов/шрифтов.
4. **`prefers-reduced-motion: reduce`** уважается ВСЕГДА. Любая анимация имеет статичный фолбэк.
5. **A11y AA минимум.** Контраст, фокус-стейты, лейблы форм, `aria-live` для статусов.
6. **Перф-бюджет.** LCP < 2.5s. Картинки только через `next/image`. Шрифты через `next/font`.
7. **Mobile-first.** Все секции верстаются с мобилы вверх.
8. **`submitLead` неприкосновенен.** Сигнатура зафиксирована в спеке §04. Меняется ТОЛЬКО внутренняя реализация (v1 → v2 канал заявок), не контракт.
9. **TypeScript strict.** Никаких `any`, `@ts-ignore` — только с обоснованием в комментарии.
10. **Чужой код — через researcher.** Перед использованием библиотеки/API — спросить researcher последние доки, не выдумывать.
