# PROJECT_IDEA — Лендинг прораба (ремонты)

> Документ Layer 1 по методологии Spec-First. Это не питч, а аналитический
> чертёж, из которого Layer 2 (SPECIFICATION.md) извлечёт параметры для сборки.
> Ни одной строки кода не пишется, пока спека не готова.

---

## 01. Проблема (конкретно, с числами)

`[ДОПУЩЕНИЕ — заменить на реальные данные прораба]`

Прораб делает ремонты квартир/домов и получает клиентов почти только через
сарафанное радио. Болевые точки:

- Нет точки в интернете. На запрос «ремонт под ключ + имя/район» в выдаче — пусто.
- Нет соц-доказательства. Десятки реальных объектов лежат фотками в галерее
  телефона, клиент их не видит → не доверяет → уходит к тем, у кого есть портфолио.
- Заявки теряются. Договорённости в переписках/звонках, часть забывается.
- Конкуренты с Avito/Profi.ru/Яндекс выглядят «как бизнес», прораб — нет,
  хотя качество работ выше.

Цена проблемы (пример для калибровки): из ~10 «тёплых» обращений в месяц
до договора доходит 2–3. Сайт с нормальным портфолио и понятным оффером
поднимает конверсию обращения→замер хотя бы на четверть — это +1 объект/мес.

## 02. Решение (пошаговый процесс, не абстракция)

Одностраничный лендинг, который за 30 секунд продаёт доверие:

1. **Hero** — кто, что делает, в каком районе/городе, главный оффер (напр.
   «бесплатный замер за 24 часа»), CTA на форму. Сильная анимация входа.
2. **Услуги** — 3–6 карточек (квартиры под ключ, санузлы, ванные, стяжка/штукатурка,
   электрика/сантехника). Без цен или «от N ₽» — по решению прораба.
3. **Before / After** — интерактивный слайдер «было/стало» по скроллу. Главный
   аргумент доверия. Это сердце лендинга.
4. **Этапы работы** — замер → смета → договор → ремонт → сдача. Снимает страх.
5. **Отзывы / гарантия** — короткие реальные отзывы + срок гарантии.
6. **Форма заявки** — имя, телефон, тип работ, комментарий. Бьёт в `submitLead()`.
7. **Контакты / футер** — телефон, WhatsApp/Telegram, зона работ.

Цель страницы (бизнес-воронка вместо «монетизации SaaS»):
заход → скролл до before/after → отправка формы → замер → договор.
Главная метрика v1 = число отправленных заявок.

## 03. Архитектура (текстовая диаграмма)

```
┌──────────────────────────────────────────────────────────┐
│  Браузер клиента                                           │
│  Next.js (App Router) · статический лендинг                │
│  Framer Motion / GSAP + ScrollTrigger · Lenis (smooth)     │
└───────────────┬────────────────────────────────────────────┘
                │  POST (имя, телефон, тип работ, коммент)
                ▼
┌──────────────────────────────────────────────────────────┐
│  submitLead()  — единая абстракция приёма заявки           │
│  Server Action (Next.js)                                   │
│                                                            │
│  v1: ЗАГЛУШКА — валидация + лог + "спасибо"                │
│  v2: подключается реальный канал (см. §06), интерфейс      │
│       submitLead() НЕ меняется                             │
└───────────────┬────────────────────────────────────────────┘
                │  (v2)
                ▼
        Telegram-бот / Google Sheets / Email — РЕШЕНИЕ ОТЛОЖЕНО
```

**Ключевое архитектурное решение:** канал доставки заявок инкапсулирован за
`submitLead()`. «Потом решим» (ТГ/Sheets/email) меняет только реализацию этой
функции, а не форму, не страницу, не деплой. БД в v1 нет.

## 04. Стек (с обоснованием)

| Слой | Технология | Почему |
|---|---|---|
| Фреймворк | Next.js 14+ (App Router), TypeScript | SSG для скорости/SEO, Server Actions под форму без отдельного бэка |
| Стили | Tailwind CSS | Совпадает с дефолтом frontend-developer-субагента, быстрый и предсказуемый |
| Анимации | Framer Motion (входы, layout) + GSAP ScrollTrigger (скролл, before/after, параллакс) | «Вау» живёт здесь, а не в дизайн-MCP |
| Плавный скролл | Lenis | Делает все скролл-анимации «дорогими» |
| Дизайн-исходник | Figma (через Figma MCP) | Реальные токены/компоненты → UI по точным размерам, не «на глаз» |
| Доки в Claude Code | Context7 MCP | Актуальные API GSAP/Framer/Next, чтобы субагент не галлюцинировал |
| Деплой | Vercel | Нативно под Next.js, бесплатно для лендинга, превью-деплои |
| БД | — (нет в v1) | Заявки уходят через `submitLead()`, хранилище не нужно |

## 06. Отложено в v2 (явные решения, не дыры)

- **Канал заявок** — РЕШЕНИЕ ОТЛОЖЕНО. Кандидаты: Telegram-бот / Google Sheets /
  Email (Formspree/Resend). Подключается внутрь `submitLead()`.
- **Дашборд прораба** — РЕШЕНИЕ ОТЛОЖЕНО. Кандидаты: канал в Telegram /
  мини-страница, читающая Google Sheet / защищённая страница позже.
- Загрузка фото объектов через админку (пока фото — в репозитории/папке).
- Аналитика (Я.Метрика/Plausible).

## 07. Конкурентный анализ

| Вариант для клиента | Что есть | Чего не хватает | Что даёт наш лендинг |
|---|---|---|---|
| Прораб сейчас (сарафан) | Доверие от знакомых | Нет онлайн-точки, нет портфолио онлайн | Витрина + захват заявок 24/7 |
| Avito / Профи.ru | Трафик, отзывы | Шаблон, прораб «как все», комиссия/конкуренция в ленте | Уникальный бренд, прямой контакт без посредника |
| Агентства ремонта | Сайт, процессы | Дорого, обезличено, субподряд | Личный прораб + цена ниже агентства |
